# 踩坑记录

只记录会重复遇到、且已有规避办法的问题。按时间倒序追加。

## 2026-11-27

### 收纳每次启动都重锚，会把用户拖好的位置拽走

- 现象：为了让收纳跟随 Dock，启动、DPI 重排、设置开启时都调用 `AnchorToDock`，用户把收纳拖到右边后，重启/切缩放又回到 Dock 上方。
- 处理：只在用户点 Dock 收纳按钮打开时锚定，并在锚定后 `SaveBounds` 写回 `CollectorX/Y`；启动、DPI 重排、设置开启只 `ApplyBounds`，沿用保存位置。
- 取舍：从 Dock 点开时仍跟随当前 Dock 所在屏；用户拖走后就按用户位置保存，直到再点 Dock 按钮。

### 外部点击收起和 Dock 收纳按钮会互相抢

- 现象：如果只判断“点在收纳窗口外就收起”，点 Dock 收纳按钮会先被外部点击逻辑收起，随后按钮再打开，形成闪一下又开。
- 处理：`CloseCollectorIfOutside` 同时排除收纳 `Bounds` 与各 Dock 的收纳按钮屏幕矩形；按钮自身交给 `ToggleCollectorFromDock` 处理。Dock 55ms 定时器用左键上升沿检测，点击收纳内部不收起。
- 验证：点按钮可收起/打开，点桌面收起，点收纳内部保持。

### DPI 变化没有重算 UiScale，Dock/灵动岛尺寸会漂移

- 现象：Windows 缩放 125% → 150% → 100% 往返后，Dock 和灵动岛没有回到原尺寸，比例看起来变大或变小。
- 原因：`V2Window` 只在句柄创建时算一次 `UiScale`，没有处理 `WM_DPICHANGED`；窗口已经在运行，DPI 已变了但布局参数仍是旧值。收纳面板还只乘 `Theme.TextScale`，漏了 DPI。
- 处理：`V2Window.WndProc` 收到 `WM_DPICHANGED` 后更新 `UiScale`，120ms 合并调用 `V2Shell.QueueDpiRefresh`，统一重排 Dock、灵动岛、收纳、Hub、设置和面板；收纳尺寸与保存改用 `UiScale`。
- 验证：100% 下 Dock 617×100、收纳 644×454 与改动前一致；125%/150% 往返需真机复测。

### Hub 右键固定后 Dock 宽度不刷新，不能只 Save 配置

- 现象：Hub 右键固定 7-Zip 后 `dockProfiles` 已写入 9 项，但副屏 Dock 仍是 576 宽、第 9 槽不出现；要重启或手动改布局才重算。
- 原因：`PinPaths` 只 `Config.Save()`，没有触发 `DockForm.Relayout`；Dock 隐藏时也不会自己重算 `bodyW`。
- 处理：`PinPaths` 成功后调用 `RelayoutDocks()`，主/副 Dock 都立即按新项数重算并重绘。
- 验证：固定后副屏 Dock 立即 `576→625`（`-1593,1442..-968,1542`），主屏仍 576；无需重启。

### 每屏 profile 以 DeviceName 为键，显示器改名会退化为共享列表

- 现象：`dockProfiles` 用 `\\.\DISPLAY2` 匹配，拔插、换主副或显卡驱动重排后 DeviceName 可能变化，profile 找不到。
- 处理：`DockItemsFor` 找不到 profile 时返回共享 `dockItems`，不写空列表、不删 profile；只有用户再次在副屏排序/移除/固定时才按新 DeviceName 新建一份。
- 取舍：宁可退回共享布局，也不按屏幕序号猜，避免把 A 屏布局套到 B 屏。

### 关闭“每屏独立布局”不能顺手清空 profiles

- 现象：最初 `SetDockPerScreen(false)` 直接 `DockProfiles.Clear()`，用户关一次开关，副屏排好的布局永久丢失。
- 处理：关闭只置 `dockPerScreen=false` 并重排，不删 profiles；重新开启时 `DockItemsFor` 继续用原 profile。只有 `ResetDock` 才显式清理。
- 验证：profile 8 项、共享 9 项时，关闭后 `profiles=1 kept=1`，副屏 576→625；再开启回 576。

### 7-Zip 的 `.lnk` 在 Dock 里图标偏小

- 现象：从 Hub 固定 7-Zip 后，Hub 内图标正常，Dock 第 9 槽只有约 10px 的小图标，hover 背景和标签正常。
- 原因：`.lnk` 走 Shell 大图标时拿到 256px 画布，但实际内容只有 16/32px，居中留白；直接铺到 44px 槽位就只剩一个小点。
- 处理：`Icons.Load` 先解析 `.lnk` 的 `TargetPath`，对目标取图标；再扫描不透明包围盒，内容不足画布 3/4 时裁边后铺满。256px 图每 4px 采样，只在新图标首次进缓存时做一次。
- 验证：7-Zip 在 Dock 第 9 槽恢复满幅，截图 `dock-shortcut-icon.png`。

### 自动隐藏副任务栏在底部热区会立刻弹回，隐藏测试要先移开光标

- 现象：`--taskbar-cycle` 隐藏两块任务栏后，副屏 `visibleAfterHide=True`；原因是光标还停在副屏底部边缘，Explorer 的自动隐藏逻辑马上把 `Shell_SecondaryTrayWnd` 重新弹出。
- 处理：诊断前把光标移到屏幕中间，再隐藏；先 `ShowWindow(SW_HIDE)` 两块实例，500ms 后统一 `SW_SHOW`。`--taskbar-cycle` 只做约 1 秒诊断。
- 验证：光标在 `1200,700` 时 `hide n=2`、两屏 False；`show n=2`、两屏 True。

### 任务栏“2px 露出”在副屏同样适用，不能用窗口底边判断

- 现象：自动隐藏时主/副任务栏 rect 都是 `y=1438..1486`，底边超出屏幕 46px，只看 `r.Bottom` 会误判为露出。
- 处理：`Revealed(Screen)` 同时要求 `r.Bottom >= screen.Bottom - 2` 且 `r.Top <= screen.Bottom - 6`；按窗口中心 x 落在哪块屏匹配实例。
- 验证：副屏任务栏露出 `-2560,1392..1440`，副屏 Dock 上移到 1296；主屏同理。

### 多屏壁纸“填充/平铺”逐屏绘制，玻璃接缝会重复

- 现象：`Wallpaper.Render` 按 `Screen.AllScreens` 逐屏 `DrawCover`，每块屏从自己的左上角重新起算，跨屏窗口的玻璃在 x=0 接缝处出现重复纹理。
- 处理：多屏时统一按虚拟屏 `DrawSpan` 连续绘制，单屏仍走系统样式；`wall` 日志记录 `span=1/0`。面板跨接缝截图 `panel-seam.png` 复核。
- 验证：双屏同 DPI 下时钟面板横跨 `-200..164`，拼接图接缝无错位/色块。

### 只放大字体、不放大承载它的 body，必然裁切

- 现象：最初只把 `Theme.Font` 的 px 乘倍率，Dock/灵动岛/面板的间距、行高和 body 仍是标准尺寸，1.3 档标题和说明互相压字。
- 处理：把倍率放到 `V2Window.DpiUiScale()`，Dock/灵动岛/面板统一吃这个 UiScale；面板和收纳的 `Cfg.W/H` 保持逻辑值，`ApplyBounds` 时再乘 `TextScale`，拖拽缩放把物理尺寸除回去。
- 验证：设置 1170×936、收纳 838×591、Dock 754×131，1.3 档截图无压字。

### WMI 亮度探测失败若每轮都重试，会把日志刷满

- 现象：控制中心 2 秒采样一次，`WmiMonitorBrightness` 在台式机/外接屏上抛“不支持”，每 2 秒写一条 warning，日志迅速膨胀，也浪费 WMI 查询。
- 处理：首次探测失败即置 `brightnessFailed`，后续采样直接返回；成功值也缓存，只有点击调亮度时再写回。日志只出现一次。
- 验证：本机启动后仅一条 `[control] 亮度接口不可用 不支持`，控制页停留 30 秒不再新增。

### 拖到 Dock 的自动化测试，必须先把 Dock 从底部热区唤出

- 现象：按住应用直接拖到 `y=1370` 时 Dock 仍在屏外，`DoDragDrop` 找不到目标，日志没有 `[drop]`，看起来像拖拽功能没实现。
- 处理：先把指针压到屏幕最底边（如 `1280,1436`）让 Dock 自动浮出，再上移到 Dock 玻璃区松手；拖拽期间 `dragging=true` 屏蔽失焦收起，放下返回 `Copy` 后再隐藏 Hub。
- 验证：`[drop] OLE 进入 Dock`、`[drop] OLE 放下 Dock`，`dockItems` 8→9。

### 自定义搜索框不会响应 Ctrl+A，自动化输入会拼串

- 现象：搜索是自绘 `query` 字符串，不是原生 `TextBox`；`SendKeys('^a')` 不能全选，接着输入就变成 `edge7-zip`，页面 0 项。
- 处理：`OnKeyDown` 显式处理 `Ctrl+A` 清空 query，Backspace 与 Esc/Enter 一并接管；自动化测试改用 `{BACKSPACE n}` 清空。
- 验证：`Ctrl+A` 后可直接输入新词，搜索 `7-zip` 正常出 2 项。

### 分层窗口用 PrintWindow 会得到全黑

- 现象：Liuli 的 V2 窗口是 `WS_EX_LAYERED` + 自绘透明，`PrintWindow` 无论 flag 0 还是 2 都输出黑图，不能作为验收证据。
- 处理：改为在当前会话用 `Graphics.CopyFromScreen` 抓屏；需要单独窗口时先 `SetWindowPos(HWND_TOPMOST)` 再裁切，抓完恢复位置。
- 验证：设置页仍可用 PrintWindow；收纳/Dock 必须走 CopyFromScreen，截图已归档。


### 自动隐藏任务栏仍有 2px 窗口，不能用 IsWindowVisible 判断“露出”

- 现象：任务栏自动隐藏后 `Shell_TrayWnd` 仍在屏幕上留 2px，且 `IsWindowVisible=true`；只看 `WorkingArea` 会把 Dock 放在 bottom-8，任务栏唤出时被 TopMost 的 Dock 盖住。
- 处理：`Taskbar.Revealed()` 同时检查 `Shell_TrayWnd` 的 rect：只有底边贴屏幕底且顶部距屏幕底 ≥6px 才算露出；`DockForm.BaseTopY` 只在自动隐藏且露出时减任务栏高度，`TickAutoHide` 每 55ms 顺带定位。
- 验证：任务栏 top=1392 时 Dock 玻璃主体底边 1384；关闭 Dock 自动隐藏截图 `docs/screens/v8/dock-above-taskbar.png`，两者不重叠。

### 日志轮转测试会吃掉真实日志

- 现象：为验证 512 KB 轮转，直接往主日志灌 581 KB，下一次写入会把整段日志移成 `.1`，原日志从 `liuli.log` 消失。
- 处理：测前把 `liuli.log` 复制到 `_scratch`；测完停止 Liuli，复制回主日志并删除 `.1`，再启动；不把测试用的 `XXX...` 行留在用户日志。
- 验证：注入后 `liuli.log` 581,641 B，触发写入后当前 52 B、`.1` 581,641 B；恢复后当前 122,125 B、无 `.1`。

### RegisterHotKey 返回值不能丢

- 现象：原逻辑直接调用 `RegisterHotKey` 却不看返回值；如果组合被其它程序占用，界面仍宣称可用，实际按了没反应。
- 处理：先 `UnregisterHotKey` 再注册 id 11/12，把两个 bool 结果写入 `HotkeyToggleOk` / `HotkeySettingsOk`，同时写日志；设置页显示“已注册/失败”，并提供“重新注册快捷键”。
- 验证：`Ctrl+Alt+G` 成功；当前机器 `Ctrl+Alt+L` 被其它进程占用，页面显示失败，日志 `toggle=fail settings=ok`。未自动换键，默认组合保持不变。

### 开机自启只写 HKCU，且每次启动要校正 exe 路径

- 现象：用户把 `Liuli.exe` 移到新目录后，`HKCU\...\Run\Liuli` 仍指向旧路径，开机启动会失败。
- 处理：`AutoStart.Apply` 每次 `V2Shell.Boot` 都按 `Config.AutoStart` 重写/删除；写入值用 `Application.ExecutablePath` 并加引号。关闭时先写注册表成功再改配置，避免开关显示已关但注册表残留。
- 验证：临时目录 `_scratch\move-test` 启动后 Run 自动改为临时路径，恢复主 exe 后回到主路径。

### 系统页加入后导航变十项

- 现象：原九页导航按 44px 行高排到 494px；加“系统”后需要 `navRects` 同步扩为 10，About 索引从 8 变 9。
- 处理：`Nav` 加“系统”保持顺序 主题/配色/面板/Dock/灵动岛/壁纸/桌面/收纳/系统/关于；`BuildPage(8)` 走 `BuildSystemPage`，`BuildPage(9)` 走 About；不写死旧索引。

### 时钟秒显示不能靠 5 秒面板 tick

- 现象：`PanelForm.tick` 原固定 5000ms，`HH:mm` 够用；加秒后秒位每 5 秒才跳一次，看起来像卡住。
- 处理：`ApplyTickInterval` 按内容设置：时钟+秒 1000ms，系统 2000ms，其它 5000ms；配置切换后遍历 `Panels` 重设间隔，不重建窗口。

### 8 字符时间在 220 宽面板会裁切

- 现象：`HH:mm:ss` 用 42px 字号时，220 宽面板内部只有约 184px，时间右侧被玻璃裁掉。
- 处理：秒显示时字号上限 32；窄高度走小字号居中；12 小时制把“上午/下午”放标题行，不再加宽主时间字符串。

### 天气离线缓存必须和“天气离线”分开

- 现象：`Weather.LoadCache` 读到旧缓存时 `Now.Has=true`，若只判断 `!Has`，断网后会继续显示“实时天气”，误导用户。
- 处理：拉取失败置 `Weather.Offline=true`，有缓存时在条件行追加“离线缓存”；完全无缓存才显示“天气离线”。

### 桌面收纳不要做“搬文件”式整理

- 现象：v1 把桌面文件真实移到 `文档\Liuli\<分组>`，会让快捷方式目标、IDE/脚本绝对路径、Office 最近文档、同步盘等外部引用失效。
- 处理：TASK-054 改为 Entry 路径索引：`CollectorItem.Path` 永远指向原文件/文件夹，分组只改 `Group`；同步只增删入口，不调用 `File.Move/Copy/Delete`。拖出面板只给 `DataFormats.FileDrop` + `DragDropEffects.Copy`，不默认移动。
- 取舍：不做多个酷呆式独立盒子，一期先单面板 + 分组标签；二期可复用同一份 `Group` 数据渲染多盒子。

### 收纳刷新用 2 秒 UI 轮询，不引入 FileSystemWatcher 跨线程

- 现象：桌面新增/删除/重命名要求 5 秒内可见；`FileSystemWatcher` 在后台线程触发，直接改 `ShellConfig` 和刷新分层窗口需要额外同步。
- 处理：`CollectorForm` 用 WinForms `Timer(2000)` 在 UI 线程调 `CollectorState.Sync(true)`；69 项目前启动/扫描无慢帧，满足 5 秒验收。后续若桌面项数上千，再评估 watcher + `BeginInvoke`。

### 收纳双击要用 OnMouseDoubleClick，单击只做按压/拖拽起点

- 现象：单击直接打开会让双击触发两次打开；面板同时要支持拖动换组。
- 处理：`OnMouseDown` 只记录 tile 起点，移动超过 8px 进入换组；`OnMouseDoubleClick` 才 `Native.ShellOpen`。拖出面板边界时启动 OLE `DoDragDrop`，只允许 Copy。

### 桌面图标隐藏后，收纳面板 tick 要再压一次

- 现象：Explorer 重启后 `SysListView32` 重新可见，原生图标与收纳面板重复。
- 处理：`CollectorForm.TickScan` 在 `CollectorAutoScan` 时每 2 秒检查 `Native.DesktopIconsVisible()`，若配置要求隐藏则再 `SetDesktopIconsVisible(false)`；不写系统“显示桌面图标”偏好。

## 2026-11-26

### 控制面板桌面图标在 Win11 25H2 不显示

- 现象：写 `HideDesktopIcons\NewStartPanel` 的 `{5399E370-B05B-11D1-9F4B-00C04FD91972}` 在 0/1 间切换，`SysListView32` 项数始终 69；原生 `desk.cpl`“桌面图标设置”预览也没有控制面板。
- 原因：Windows 11 25H2 build 26200 桌面已不绘制该图标，不是注册表键或刷新路径问题；`SHChangeNotify`、Explorer 重启、`ClassicStartMenu` 都无效。
- 处理：保留开关与注册表写入，设置页提示“Win11 25H2 可能看不到图标”，不把它当失败；Win10 1903 未回归。

### 桌面图标运行期隐藏不要用 WM_COMMAND 0x7402

- 现象：v1 `Native.ToggleDesktopIcons` 发 `WM_COMMAND 0x7402` 可切换桌面图标，但它改的是系统显示偏好，不区分“本次运行临时隐藏”。
- 处理：v2 只对 `SHELLDLL_DefView` 下的 `SysListView32` 调 `ShowWindow(SW_HIDE/SW_SHOW)`；启动记录原状态、写 `desktop-icons.runtime` 标记，正常退出恢复。系统图标偏好才写注册表。

### 桌面项数不能靠截图判断

- 现象：Explorer 重启后截图左侧看不到“此电脑”，但 `LVM_GETITEMCOUNT` 返回 70，说明图标在截图区域外或被其他窗口遮挡。
- 处理：验证桌面图标一律用 `SysListView32` 的 `LVM_GETITEMCOUNT` + `IsWindowVisible`，截图只作辅助。

### 原生文件对话框：SetWindowText / BM_CLICK 不触发选中

- 现象：向“选择壁纸”的 Edit 控件 `SetWindowText` 能写入完整路径，但“打开”按钮保持禁用，`BM_CLICK`、Enter、对按钮 `PostMessage` 均不提交。
- 原因：Common Item Dialog 依赖真实编辑框的 `EN_CHANGE`/键盘焦点状态，程序化改文本不会触发按钮启用。
- 处理：真实鼠标点文件名框获得焦点，剪贴板放路径后发真实 `Ctrl+V` + `Enter`；`SetForegroundWindow` 在后台进程常返回 false，不要只靠 SendKeys。UIA 树只暴露部分控件，不能依赖 UIA 找文件名框。

### 压暗重烘后 tone 仍用旧壁纸明暗

- 现象：改 `wallpaperDim` 后玻璃底已重烘，但设置页仍是旧明暗/强调色，日志里重烘与主题应用顺序不明显。
- 原因：`ApplyVisualSettings` 只在重烘前应用主题，`Backdrop.Rebuild` 更新 `Light/Mean/Accent` 后没有第二次 `ApplyTheme`；`LoadTheme` 同样可能先重烘后套主题。
- 处理：`ApplyVisualSettings(true)` 与 `LoadTheme` 都改为 `ApplyTheme → Rebuild → ApplyTheme`；`Backdrop.Rebuild` 日志追加 `dim/mean/light`，可直接核对压暗是否进入平均色。注意设置页浅色背景可能只是预览卡片本身，判断主题应看导航/标题文字与日志 `light`。

### 测试壁纸污染 `wallpaperOrig`，恢复仍回到测试图

- 现象：测试中先手动把系统壁纸换成测试图，再调用 `SetWallpaperImage`，`wallpaperOrig` 记录成测试图；点“恢复系统壁纸”后系统壁纸仍是测试图。
- 原因：`WallpaperOrig` 只捕获“首次换图前”的当前系统壁纸；测试前没先恢复真实原图，捕获到的就是测试态。
- 处理：每轮壁纸测试前先用 `SystemParametersInfo(0x0014)` 恢复 `C:\WINDOWS\web\wallpaper\Windows\img0.jpg`，再启动外壳；验收结束用 `_scratch/shell-before-wallpaper.json` 回滚配置。

### 分层窗口截图：PrintWindow 出黑图

- 现象：设置窗 `PrintWindow` 能拿到完整 900×720；Dock/灵动岛同法只有黑图。
- 原因：Dock/灵动岛用 `UpdateLayeredWindow` 自绘，`PrintWindow` 不合成分层内容。
- 处理：Dock/灵动岛改用主屏 `CopyFromScreen` 后按窗口 rect 裁剪；设置窗仍用 `PrintWindow` 最稳。

### 颜色对话框：PostMessage 点不动色块

- 现象：向 `#32770` 颜色对话框 PostMessage 鼠标消息，选中色/确定均不生效；`SetDlgItemInt(706/707/708)` 也不改变最终结果。
- 原因：Common ColorDialog 在模态循环里按真实鼠标状态取值，不认伪造的窗口消息。
- 处理：用 `SetCursorPos` + `mouse_event` 发真实输入；点基本色块再点“确定”，配置写入 `#FF80FF`。取消路径同样用真实输入回 `#FF80FF` 不变。

### CU 截屏是 PIP 桌面，外壳在主桌面

- 现象：`cu.screenshot()` 看不到刚启动的 `Liuli.exe` 设置窗，但 `EnumWindows` 能拿到 `830,360,1730,1080`。
- 原因：CU 当前桌面是 PIP；`Start-Process` 启动的外壳在主桌面（或另一桌面上下文）。
- 处理：本轮改用 PowerShell `CopyFromScreen` 截主屏、`EnumWindows` 定位窗口并用 `PostMessage`/真实鼠标操作；不要用 CU 截图判断主桌面窗口是否存在。

### 面板“置底”无效：`V2Window` 无条件加 TOPMOST

- 现象：面板 `TopMost=false` 仍压在普通窗口上，ExStyle 始终含 `WS_EX_TOPMOST (0x8)`。
- 原因：`V2Window.CreateParams` 无条件 `cp.ExStyle |= WS_EX_TOPMOST`。
- 处理：改为 `if (TopMost) cp.ExStyle |= WS_EX_TOPMOST`；置底后 `0x08090080`，置顶 `0x08090088`。

### 面板坐标是 body 不是窗口

- 现象：配置 `x/y` 与 `GetWindowRect` 相差 12px，容易误判拖动偏移。
- 原因：面板窗口四周留 12 逻辑像素阴影，配置只存玻璃 body 左上角。
- 处理：写盘/拖动/缩放统一用 body 坐标；窗口 Location = `(X-12,Y-12)`，命中测试按 body 判断。

### 任务栏常显时 Dock 多上移 48px

- 现象：任务栏从自动隐藏切到常显，Dock top 1344→1248，比预期多上移一个任务栏高度。
- 原因：`Screen.PrimaryScreen.WorkingArea.Bottom` 已扣除任务栏，`BaseTopY()` 又减了 `Taskbar.VisibleHeight()`。
- 处理：只读 `WorkingArea.Bottom - 8`，不再二次扣；修复后 top=1296。详见 Issue #47。

### `git push` 连接重置

- 现象：`Recv failure: Connection was reset`，偶发超时。
- 处理：等待几秒后重试，通常第 2–3 次成功；不是仓库权限或分支问题。

### `gh issue create` 走 GraphQL 500

- 现象：`gh issue create` 偶发 GraphQL 500，中文正文更容易触发。
- 处理：改用 REST `gh api -X POST repos/<owner>/<repo>/issues --input <json>`；JSON 用 `ConvertTo-Json -Compress` 或文件，正文里的换行用 `` `n ``。

### PowerShell 改 C# 文件把 LF 变 CRLF

- 现象：`Set-Content` 默认编码/换行把整文件变成 CRLF，diff 变成整文件。
- 处理：用 `[System.Text.UTF8Encoding]::new($true)` 写 UTF-8 BOM，并 `.Replace("`r`n","`n")`；改完用 `git diff --stat` 确认不是整文件 diff。

### 构建时 `Liuli.exe` 被预览进程锁住

- 现象：`build.ps1` 复制输出失败，提示文件被占用。
- 处理：先 `Get-Process Liuli`，有残留就 `Stop-Process`；`--preview` 退出后也会短暂占用，等 1–2 秒再构建。

### `--preview` 会改写已提交的预览图

- 现象：每次预览用当前时间重绘 `m1-preview.png` / `m1-preview-pressed.png`，产生无关 diff。
- 处理：提交前 `git status`，对不相关预览执行 `git restore -- docs/screens/v2/...`；只保留本次要留档的新图。

### 控制台中文 mojibake

- 现象：`--selftest` 在 PowerShell 里中文显示为乱码，但键值可读。
- 处理：以 UTF-8 文档为准，不按控制台乱码改源码；需要核对中文时读文件。

### 设置页主题命名被输入法候选窗干扰

- 现象：`SendKeys("Evening")` 时输入法候选窗抢焦点，最终保存成默认“主题 1”；剪贴板粘贴又会追加到默认名。
- 处理：`CommitName` 前 `ActiveControl = null; Application.DoEvents();` 让原生 TextBox 失焦后再读 `Text`；命名框打开时默认全选，用户直接输入即可替换。直接中文键入尚未复测。

### 设置页改滑杆后“当前主题”徽标不刷新

- 现象：`ApplyVisualSettings` 清空 `ActiveTheme`，但设置页控件仍是改前构建的，“当前”徽标和底部文案停留旧值。
- 处理：设置表单加 180ms `Timer`，滑杆松手/开关切换后重建页面；拖动中与命名中跳过，避免控件被重建。

### 720 高度塞不下 6 个面板/主题行

- 现象：面板行 82px + 头部会越过 680 底部栏；灵动岛三开关也会压到底栏。
- 处理：面板行压到 72/76、主题行 78/84；灵动岛滑杆 64、内容开关 54；6 面板/6 主题在 100% DPI 下刚好落在底栏上方，125% DPI 仍需复测。

### 自动化点击不要拿截图裁剪坐标当客户区坐标

- 现象：从 `CopyFromScreen(800,340)` 的截图读像素，和窗口客户区 `830,360` 差 30/20，点主题“加载”会落到左侧空白。
- 处理：用 `GetWindowRect` 得到窗口原点，`PostMessage(WM_LBUTTONDOWN)` 的 `lParam` 用 `屏幕坐标-窗口原点`；Dock 齿轮在客户区 `x≈512..548`，不是截图里的视觉中心。

### C# 5 编译限制

- 现象：`csc.exe` 不接受字符串插值、`?.`、`nameof`、表达式体成员。
- 处理：用 `string.Format` / 拼接、显式 null 判断、完整属性/方法体；构建脚本固定 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。

### 分层窗口挂不上 DWM Mica

- 现象：`WS_EX_LAYERED` + ULW 自绘窗口无法直接使用 DWM Mica。

## 2026-11-27

### 多屏 Dock 只判 Y 导致所有屏同时弹出

- 现象：两块屏各有一个 Dock，鼠标放到任一屏底部，两块 Dock 同时露出。
- 原因：`TickAutoHide` 只判 `p.Y >= screenBounds.Bottom - hot`，没有判 X 是否落在本屏。
- 处理：改为 `screenBounds.Contains(p) && p.Y >= ...`；每屏 Dock 只响应本屏底部热区。

### `WM_DISPLAYCHANGE` 与 `SystemEvents` 双触发

- 现象：同时挂 `SystemEvents.DisplaySettingsChanged` 和 `V2Host.WndProc` 的 `0x007E`，一次显示器变化会重排两遍，副屏 Dock 可能重建两次。
- 处理：只保留 `WM_DISPLAYCHANGE` 入口，`DisplayChanged()` 直接调 `OnDisplayChanged()`；不再额外挂 `SystemEvents`。
