## 1. 背景与问题

Liuli 最初的目标是做一个 GlassBoard 式的 Windows 桌面美化工具。GlassBoard 的核心不是文件整理，而是：

1. 毛玻璃 Dock
2. Windows 灵动岛
3. 面板与主题
4. 桌面组件（时钟、天气、系统、音乐、图标收纳）
5. 壁纸与外观
6. 设置、全局热键、开机自启、高分屏适配
7. 应用面板与控制中心（扩展）

v1.x 实际把范围收窄成了“玻璃看板 + 文件整理 + 收纳目录同步”，偏离了原始需求。v1.5.0 之后停止在这条线上继续加功能。

---

## 2. 产品定义

**一句话**：Liuli 是一个单 exe、零外部 DLL、离线可用的 Windows 桌面美化套件，用毛玻璃 Dock、顶部灵动岛、可自由摆放的玻璃面板与桌面组件，复刻 GlassBoard 的核心体验。

**目标用户**：作者本人与朋友；Windows 10/11 日常桌面用户；希望桌面更整洁、更好看，但不想装重型美化软件。

**平台**：Windows 10 1903 及以上 / Windows 11；首版以单主屏、100%–150% 缩放为验证基线。

**成功标准**：

- 用户可以不打开旧“看板”功能，只靠 Dock、灵动岛、面板与组件完成日常桌面使用。
- 核心功能离线可用；天气除外，失败自动退回缓存。
- 常驻内存 < 80MB，闲置 CPU < 1%，启动到可见 < 3 秒。
- 视觉上能一眼认出是同一套 GlassBoard 语言：毛玻璃、圆角、顶边高光、统一描边、克制的强调色。

## 3. 范围与封存

### 3.1 封存（FROZEN）

以下 v1.x 用户功能整体封存：代码保留、配置保留、入口隐藏，不在 2.0 首版继续开发：

- FROZEN-001 便签 / 待办 / 代码 / 状态 / 文件 / 时钟六类“看板”作为独立产品功能
- FROZEN-002 一键整理桌面图标、撤销整理、移动原件、`groups.txt` 分组规则
- FROZEN-003 文件看板绑定收纳目录、4 秒双向同步、拖入移动原件
- FROZEN-004 备份导出/导入、恢复默认布局等旧设置入口
- FROZEN-005 视频壁纸（WMP 挂 WorkerW）；静态壁纸能力保留
- FROZEN-006 旧“新建看板”右键菜单、双击控制条开设置等旧交互

封存不等于删除。`boards.json`、收纳目录、用户文件都不动；2.0 使用独立配置，避免升级破坏旧数据。

### 3.2 保留并复用的技术资产

- `Backdrop`：从壁纸文件烘焙磨砂底，按屏幕坐标切片；不截屏。
- `Glass` / `Theme`：投影、薄纱、渐变、噪点、描边、顶边高光、圆角与 token。
- `Native`：`UpdateLayeredWindow`、DWM 亚克力、热键、拖放、DPI、桌面层。
- `Store`：极简 JSON、原子写入、坏文件回退。
- `Weather` / `Stats`：天气缓存与 WMO 图标、CPU/内存/磁盘采样。
- `Log` / `Paths` / 单实例 / 托盘 / 开机自启。
- `Icons` 的 Shell 图标缓存与图标网格绘制：仅作为 2.0“图标收纳组件”的实现参考，不直接恢复旧看板入口。

## 5. 功能需求

### 5.1 应用外壳与生命周期

**REQ-001（P0）启动与常驻**
系统应在启动后 3 秒内显示 Dock 与灵动岛；默认不替换任务栏、不修改系统主题、不要求管理员权限；任务栏隐藏按 REQ-005 单独开关。
验收：冷启动计时 ≤ 3s；任务栏仍由 Windows 管理；普通用户权限可运行。

**REQ-002（P0）单实例与配置安全**
系统应保证同一用户只有一个 Liuli 进程；配置写入必须原子替换，坏配置回退到上一份可用配置。
验收：重复启动第二个进程自动退出；断电模拟后配置仍可加载。

**REQ-003（P0）一键隐藏**
用户按全局热键时，系统应在 100ms 内隐藏 Dock、灵动岛、所有面板与组件；再次按下恢复。
验收：热键响应可感知无延迟；全屏游戏/演示时可一键清空视觉层。

**REQ-004（P0）退出清理**
用户退出时，系统应保存配置、注销热键、移除托盘图标，并恢复被临时修改的系统状态。
验收：退出后无残留进程、无残留顶层窗口；桌面壁纸与图标状态恢复。

**REQ-005（P0）任务栏自动隐藏**
系统应能自动把 Windows 任务栏设为“自动隐藏”，并持久化到下次登录；首次修改前记录原状态，设置中提供“恢复系统任务栏”。
验收：设置后任务栏缩到屏幕边缘，鼠标移到边缘可唤出；重启/重新登录后仍保持；点“恢复”后回到用户原来的状态。

**REQ-006（P1）运行期完全隐藏任务栏**
系统宜提供可选的“运行期完全隐藏任务栏”：仅在 Liuli 运行期间隐藏 `Shell_TrayWnd`，退出/崩溃恢复后重新显示；不修改 Explorer 文件、不替换系统外壳。
验收：开启后任务栏不占屏幕；Win 键、开始菜单、搜索仍可用；退出 Liuli 后任务栏恢复；异常退出下次启动自动校准。

**REQ-007（P0）Dock 与任务栏避让**
任务栏自动隐藏时，Dock 贴屏幕底部 8px；任务栏被鼠标唤出时，Dock 应上移任务栏高度或暂时淡出，避免互相遮挡。
验收：鼠标扫过底部时任务栏与 Dock 都能正常使用；不出现闪烁、焦点抢占或 Dock 被永久顶起。

### 5.2 Dock

**REQ-010（P0）位置与避让**
Dock 应默认位于主屏底部居中；任务栏常显时在其上方，任务栏自动隐藏时贴底 8px，并按 REQ-007 在任务栏唤出时避让。
验收：1366×768 与 2560×1440 下均完整可见；任务栏自动隐藏弹出时 Dock 不被永久遮挡。

**REQ-011（P0）固定与持久化**
用户应能把 `.lnk`、`.exe`、文件夹或普通文件拖到 Dock 固定；重启后保持；重复路径不重复添加。
验收：拖入 4 类对象各 1 个，重启后仍在；同一路径拖两次只出现 1 个。

**REQ-012（P0）启动**
用户左键单击 Dock 图标时，系统应通过 Shell 默认方式打开目标；目标不存在时给出非阻塞提示。
验收：Chrome 快捷方式、文件夹、txt 文件均可打开；删除目标后点击只提示、不崩溃。

**REQ-013（P0）移除与排序**
用户右键 Dock 图标应能“取消固定”；P1 支持拖拽排序。
验收：右键移除后立即重绘并持久化；不误删源文件。

**REQ-014（P0）自动隐藏**
Dock 应支持“常显 / 自动隐藏”两种模式；自动隐藏时鼠标进入底部热区应唤出，离开后延时收起。
验收：热区高度 ≤ 8px；唤出/收起动画 ≤ 200ms；不抢焦点。

**REQ-015（P0）外观**
Dock 应使用统一玻璃材质；支持图标尺寸、间距、整体缩放三档预设；悬停图标有放大反馈。
验收：三档预设可切换并持久化；与灵动岛、面板同一套圆角/描边/高光。

**REQ-016（P1）运行状态**
Dock 宜显示应用是否正在运行（小圆点），并在启动时给出轻量反馈。
验收：已运行应用有指示；指示不引入进程枚举卡顿。

**REQ-017（P0）默认应用组合**
Dock 首次启动应自动生成一组混合默认项：系统入口（此电脑、回收站、用户文件夹）+ Windows 自带应用（文件资源管理器、设置、Edge、记事本、计算器）；缺失的程序自动跳过；用户删除后重启不自动补回，只有“恢复默认”才重建。
验收：首次启动至少 2 个系统入口和 3 个自带应用；删除后重启仍为空缺；恢复默认后完整重建。

**REQ-018（P0）系统入口段**
Dock 应在左侧显示“系统入口”段，与固定应用段用分隔线隔开；五个系统入口各有独立的“在 Dock 显示”开关，与桌面图标开关解耦；点击“此电脑”打开资源管理器，“回收站”打开回收站，“用户文件夹”打开用户目录。
验收：桌面隐藏不影响 Dock 入口；Dock 关闭不影响桌面开关；最多 5 个，不重复；右键可单独移除。

**REQ-019（P0）图标清晰度与脚标**
Dock 图标应优先取 256px Shell 大图标并高质量缩放；默认去除快捷方式小箭头脚标，可在设置中恢复。
验收：100%/150% 缩放下图标不糊；`.lnk` 图标无箭头；开关切换后立即重绘。

**Dock 待核对清单（GlassBoard 实测后定稿，不先写代码）**

- 自动隐藏的触发方式、延时、边缘热区高度
- 图标悬停放大曲线、启动反馈、运行指示点、未读角标
- 图标高清化与去脚标的默认值
- 是否支持分组、滚轮切换、分页
- 控制中心/音量/电源等小按钮是否属于 Dock
- 从应用面板拖入、拖拽排序、右键菜单完整项
- 与任务栏的关系：只做悬浮层，还是允许替代任务栏
- 多屏时每屏独立 Dock 还是只主屏

这些先作为“待核对”，不在需求确认前凭印象实现。

### 5.3 灵动岛

**REQ-020（P0）收起态**
灵动岛应收起为顶部居中胶囊，显示当前时间与天气摘要（天气不可用时显示 CPU 或离线状态）；胶囊外区域点击穿透。
验收：不遮挡桌面顶部操作；透明区域不拦截鼠标；时间每分钟更新。

**REQ-021（P0）展开态**
鼠标悬停 150ms 后应展开，显示日期、天气详情、CPU/内存/磁盘；离开 1 秒后收起。
验收：展开/收起无闪烁；连续悬停不抖动；展开区不超出屏幕。

**REQ-022（P0）快捷动作**
展开态应提供“新建组件 / 整理 / 设置”三个快捷动作；点击非按钮区域打开设置。
验收：三个动作均可用；点击空白不误触其它按钮。

**REQ-023（P1）媒体**
灵动岛应显示当前媒体标题、艺术家、进度，并支持播放/暂停/上一首/下一首。
验收：SMTC 可用时 1 秒内同步；不可用时隐藏媒体区，不报错。

**REQ-024（P1）通知**
灵动岛宜在不打扰的前提下显示系统通知摘要；支持忽略与清除。
验收：通知出现/消失有过渡；不重复弹同一条；不读取通知正文以外的隐私内容。

**REQ-025（P0）可配置**
用户应能调整灵动岛宽度、高度、顶部偏移、展开动画时长与显示内容开关。
验收：修改后立即预览并持久化；越界值自动收敛到安全范围。

### 5.4 面板与主题

**REQ-030（P0）玻璃面板**
系统应提供可自由摆放、缩放、置顶/置底的玻璃面板；面板外部点击穿透，内部可命中。
验收：拖动/缩放流畅；空白区域不挡桌面图标；圆角与投影无锯齿。

**REQ-031（P0）面板内容**
面板应支持空容器、时钟、天气、系统读数四类首版内容；内容与容器解耦。
验收：同一面板可切换内容类型；切换不丢位置与尺寸。

**REQ-032（P0）主题保存/加载**
用户应能把当前面板布局、Dock/灵动岛参数、壁纸与配色保存为命名主题；支持加载、覆盖、删除。
验收：保存后重启仍可加载；加载主题不修改用户文件；坏主题文件不破坏当前配置。

**REQ-033（P1）导入推荐配置**
系统应支持导入 GlassBoard 风格的 JSON 推荐配置；导入前自动备份，字段校验失败时整单拒绝并提示。
验收：合法配置一次应用；非法字段有明确错误；失败后当前状态不变。

**REQ-034（P0）视觉一致性**
所有可见组件应只使用 `Theme` / `Glass` 的圆角、描边、投影、字体与强调色 token。
验收：代码审查无窗口自创材质参数；截图中高光/描边方向一致。

### 5.5 桌面组件

**REQ-040（P0）时钟**
组件应显示时间与日期，支持 12/24 小时制与秒显示开关。
验收：跨分钟/跨天正确刷新；不因定时器累积漂移。

**REQ-041（P0）天气**
组件应显示当前温度、天气状况、湿度与风；离线时显示缓存并标注。
验收：联网刷新 ≤ 30 分钟；断网不空白、不崩溃。

**REQ-042（P0）系统读数**
组件应显示 CPU、内存、磁盘占用，采样频率不高于 2 秒一次。
验收：读数与任务管理器趋势一致；空闲采样 CPU 开销可忽略。

**REQ-043（P1）音乐**
组件应显示封面、标题、艺术家、进度与基础控制。
验收：SMTC 有媒体时可用；无媒体时显示占位。

**REQ-044（P1）图标收纳**
组件应能绑定一个文件夹，以图标网格显示；支持单击打开、拖出到资源管理器、外部变更后刷新。
验收：绑定目录新增/删除/重命名后 5 秒内对齐；不移动源文件，除非用户显式开启。

**REQ-045（P0）摆放与吸附**
组件应支持自由摆放、边缘吸附、锁定、隐藏与恢复；位置持久化。
验收：重启后位置一致；多组件重叠时可置顶/置底。

### 5.6 壁纸与外观

**REQ-050（P0）壁纸读取与预览**
系统应读取当前 Windows 壁纸并在设置中预览；玻璃底从壁纸文件烘焙，不截屏。
验收：换壁纸后玻璃底在 5 秒内更新；窗口/图标不会进入玻璃底。

**REQ-051（P0）切换图片壁纸**
用户应能选择本地图片作为壁纸，应用后立即生效，并可恢复系统壁纸。
验收：jpg/png/bmp/webp 可用；恢复后系统原壁纸回来。

**REQ-052（P0）压暗与色调**
用户应能调整壁纸压暗与明暗模式；调整后所有组件同步更新。
验收：滑块 0–80% 生效；重启保持。

**REQ-053（P0）跟随壁纸自动变色**
系统应在“跟随壁纸”开关打开时，从当前壁纸提取主色与明暗，生成一套完整配色（强调色、玻璃染色、文字色、描边色、阴影色）；换壁纸后 5 秒内整体更新。
验收：开关打开时换壁纸，Dock、灵动岛、面板、组件同时变色；关闭后保持当前预设/自定义配色，不再随壁纸变化。

**REQ-054（P0）内置预设风格**
系统应提供至少 6 套内置配色预设（如雾蓝、石墨、暖砂、青瓷、紫雾、极简白），每套包含明暗、强调色、玻璃染色与文字层级。
验收：预设可一键切换并持久化；所有组件同步；重启后保持。

**REQ-055（P0）自定义配色**
用户应能自定义强调色、明暗模式、玻璃浓度、描边强度与文字对比；修改后全局生效，不允许单个组件单独配色。
验收：自定义值越界自动收敛；确认后所有组件同步；可保存为命名主题。

**REQ-056（P0）统一与可读性**
系统应对所有可见组件使用同一套 Theme token，并按背景亮度自动选择文字明暗；主文字对比度不低于 4.5:1（按玻璃合成底色估算）。
验收：任意预设/壁纸下，标题、正文、次要文字层级清晰；代码审查无组件自创颜色。

**REQ-057（P0）取色性能与回退**
配色提取应只在换壁纸、切预设或改自定义值时计算一次，不进入逐帧绘制；取色失败时回退到当前预设。
验收：配色重算 ≤ 500ms；连续拖动滑块不卡顿；低饱和/高对比壁纸不产生刺眼强调色。

### 5.7 设置与系统

**REQ-060（P0）分模块设置**
设置应包含：灵动岛、壁纸、配色、面板与主题、Dock、桌面组件、快捷键与开关、通用、关于。
验收：每个模块有独立页面；切换不丢未保存的临时值。

**REQ-061（P0）开机自启**
用户应能开关当前用户开机自启；移动 exe 后启动项仍指向新路径。
验收：写入 `HKCU\...\Run`；关闭后删除；不写 HKLM。

**REQ-062（P0）HiDPI**
系统应在 100%–150% 缩放下保持文字、圆角、图标清晰；不支持时给出降级而不是错位。
验收：125%/150% 真机截图无糊边、无越界。

**REQ-063（P0）全局热键**
系统应提供默认 `Ctrl+Alt+L` 隐藏/恢复全部视觉层，并允许在设置中查看与重置。
验收：与其它软件冲突时提示；重置后立即生效。

**REQ-064（P0）日志与诊断**
系统应记录启动、配置、拖放、异常，日志超过 512KB 轮转；设置中可打开日志目录。
验收：异常有堆栈；日志不无限增长。

### 5.8 应用面板与控制中心（P1）

**REQ-070（P1）应用面板**
系统宜提供应用网格/搜索，支持从面板拖到 Dock 固定。
验收：常用应用可启动；拖到 Dock 后固定成功。

**REQ-071（P1）控制中心**
系统宜提供音量、网络、蓝牙等快捷状态；不可用时隐藏对应项。
验收：不引入额外常驻服务；系统 API 失败时不影响主界面。

### 5.9 桌面图标与系统入口

**REQ-080（P0）默认隐藏桌面图标**
系统应在启动时默认隐藏桌面图标，只保留壁纸与 Liuli 组件；用户可在设置中改为“显示桌面图标”。
验收：首次启动桌面图标不可见；切换为显示后立即恢复；不删除任何文件或快捷方式。

**REQ-081（P0）系统图标桌面开关**
系统应支持分别控制“此电脑、回收站、用户文件夹、网络、控制面板”五个系统图标在桌面上的显示状态；默认全部关闭。
验收：五个开关互不影响；切换后 2 秒内桌面生效；资源管理器重启后仍保持；不生成或删除快捷方式。

**REQ-082（P0）启动应用与退出恢复**
系统应在启动时记录桌面图标原始状态，再应用 Liuli 配置；正常退出时恢复“运行期隐藏”的部分，不把临时隐藏写成永久系统设置。
验收：隐藏全部图标属于运行期状态，退出后恢复；系统图标桌面开关属于用户显式偏好，退出后保持；异常退出下次启动可重新校准。

**REQ-083（P0）Dock 系统入口**
Dock 应在左侧显示“系统入口”段，五个系统图标各有独立的“在 Dock 显示”开关，与桌面开关解耦；默认显示“此电脑、回收站、用户文件夹”，网络与控制面板默认关闭。
验收：桌面隐藏不影响 Dock 入口；Dock 关闭不影响桌面开关；点击此电脑打开资源管理器，点击回收站打开回收站；最多 5 个，不重复；系统段与固定应用之间有分隔线。

**REQ-084（P1）系统图标自动同步**
系统图标被 Windows 设置或其它工具改变时，Dock 入口应在 2 秒内同步可用状态（存在/不存在），不要求重启 Liuli；桌面可见性与 Dock 可见性分别保存，互不覆盖。
验收：外部改动后 Dock 入口可用状态一致；不轮询到明显 CPU 开销。

**REQ-085（P1）桌面新图标收纳**
桌面出现新文件/快捷方式时，系统宜按用户规则自动加入“桌面收纳”组件或给出提示；默认只加入口，不移动源文件。
验收：新文件 5 秒内可见；不自动删除、不自动移动；可关闭。

### 5.10 屏幕适配与文字排版

**REQ-090（P0）Per-Monitor DPI**
系统应启用 Per-Monitor V2 DPI 感知，按窗口所在显示器的 DPI 计算尺寸、字体、圆角与图标，不使用全局单一缩放。
验收：100% 主屏 + 150% 外接屏同时使用时，两块屏上的 Dock、灵动岛、面板都清晰，无拉伸模糊、无越界。

**REQ-091（P0）响应式布局**
所有组件尺寸应以 96 DPI 逻辑单位定义，再按当前屏 DPI 与用户文字倍率换算；Dock 最大宽度不超过工作区 70%，超出时压缩间距或换行；设置页内容超高时可滚动。
验收：1366×768@100%、1920×1080@125%、2560×1440@150%、3840×2160@200% 下无文字裁切、无按钮重叠。

**REQ-092（P0）文字大小适配**
系统应提供“小 / 标准 / 大 / 特大”四档 UI 文字倍率（建议 0.9 / 1.0 / 1.15 / 1.3），并可选跟随 Windows 辅助功能文字缩放；最小正文不小于 8pt。
验收：四档切换后全局同步；中文标题/正文/次要文字不重叠、不截断；超长文件名显示省略号并可悬停看全名。

**REQ-093（P0）单屏/多屏模式**
系统应默认只在一台主屏显示全部组件；用户可开启多屏，选择“仅主屏 / 所有屏 Dock + 主屏灵动岛 / 自定义每屏布局”。
验收：默认单屏不影响副屏；开启多屏后每块屏的 Dock 独立可用；灵动岛默认只出现在主屏。

**REQ-094（P0）显示器变化**
系统应在显示器热插拔、分辨率变化、DPI 变化、主屏切换后 2 秒内重新布局；越界窗口自动收回工作区。
验收：拔掉外接屏后组件回到主屏可见范围；重新接回后恢复上次每屏位置（P1）。

**REQ-095（P1）多任务栏隐藏**
开启任务栏隐藏时，系统应同时处理主任务栏与副屏任务栏（`Shell_TrayWnd` / `Shell_SecondaryTrayWnd`），退出时全部恢复。
验收：多屏任务栏都能隐藏与恢复；不出现只隐藏主屏、副屏仍占位。

**REQ-096（P1）壁纸切片跨屏一致**
多屏且 DPI 不同时，玻璃底应按虚拟屏物理坐标切片，跨屏拼接处不出现色差、错位或重复纹理。
验收：双屏扩展模式下横跨两屏的窗口，玻璃纹理连续；换壁纸后 5 秒内一致。

**REQ-097（P0）性能分档**
1080p 单屏常驻内存目标 < 80MB；4K 或多屏允许提高到 < 120MB，但闲置 CPU 仍 < 1%。
验收：对应分辨率下任务管理器读数达标；切换屏幕不反复重建整屏底图。

### 5.11 视觉质量

**REQ-100（P0）统一设计语言**
所有可见界面应使用同一套设计语言：圆角、间距阶梯（4/8/12/16/24）、字号层级、描边、阴影、图标线宽与强调色规则；不允许窗口各自发明样式。
验收：代码审查无组件自创圆角/颜色/阴影；截图中同类元素视觉一致。

**REQ-101（P0）排版与对齐**
界面应遵循 4px 网格与统一内边距；标题、正文、次要文字层级清楚；文字不压边、不重叠、不裁切；同屏强调色不超过一个主色。
验收：1366×768 与 4K 截图逐项检查；无“挤在一起”或“空得发慌”的区块。

**REQ-102（P0）材质完整度**
玻璃面板应有完整的投影、薄纱、顶边高光、上亮下暗描边与噪点；不能出现纯色方块、默认 WinForms 灰底、直角白框或系统默认滚动条裸露。
验收：浅色壁纸、深色壁纸、高饱和壁纸三种背景下材质都成立；文字对比度达标。

**REQ-103（P0）动效克制**
展开、收起、悬停放大、自动隐藏应使用统一缓动（建议 120–240ms，ease-out），不闪烁、不抽搐、不抢焦点；动效服务于层级，不做无意义弹跳。
验收：连续操作 10 次无可感知卡顿；动画中途反向操作不出现残影。

**REQ-104（P0）视觉验收闸门**
每个里程碑应产出同角度截图，按“对齐/间距/字号/材质/配色/动效”六项清单评审；任一 P0 视觉缺陷未修不得进入下一阶段。
验收：截图存档在 `docs/screens/v2/`；评审记录写入 Issue；用户确认“看起来是成品”而不是“功能能用”。

**REQ-105（P1）视觉细节打磨**
在 V2 阶段补齐底边折射、强调色呼吸、图标高清化、文字抗锯齿、圆角与描边在 125%/150% 下的像素对齐。
验收：100%/125%/150%/200% 截图无明显锯齿、糊边、错位。

**适配测试矩阵（设计阶段用）**

| 场景 | 分辨率 | 缩放 | 重点 |
| --- | --- | --- | --- |
| 小笔记本 | 1366×768 | 100% | Dock 宽度、设置页滚动、文字不裁切 |
| 主流轻薄本 | 1920×1080 | 125% | 字体清晰度、圆角、图标 |
| 2K 台式 | 2560×1440 | 100%/150% | Dock 比例、灵动岛宽度 |

## 7. 视觉推进策略

不做“一次性像素级复刻”。按三层推进：

1. **V0 结构对齐**：先保证 Dock、灵动岛、面板的位置、层级、信息密度与 GlassBoard 一致。
2. **V1 比例与材质对齐**：圆角、留白、字号、图标尺寸、玻璃透明度、阴影范围逐项对照参考截图调整。
3. **V2 动效与细节**：悬停放大、展开弹簧、自动隐藏、强调色呼吸、噪点与底边折射。

每个里程碑必须产出同角度截图，与参考图并排评审；没有截图不算完成。

## 9. 明确不做

- 不替代 Windows 任务栏、开始菜单、窗口标题栏；只按开关隐藏或避让，不替换系统外壳。
- 不做“永久删除任务栏 / 替换 Explorer”这类不可逆改动；完全隐藏仅限 Liuli 运行期间，退出恢复。
- 不做账号、云同步、在线主题市场、安装器、广告。
- 不做整屏截屏玻璃、不做注入 Explorer、不做需要管理员权限的桌面接管。
- 不恢复 v1.x 的“看板 + 一键整理 + 收纳同步”作为主功能。
- 不复制 GlassBoard 的代码、图片、字体或配置文件；只参考机制、参数与交互结论。

1. Dock 默认常显还是自动隐藏？建议默认常显，自动隐藏作为开关。
2. 旧看板是否在 2.0 中完全不可见？建议完全隐藏，数据保留，不提供“旧版入口”。
3. 灵动岛首版是否必须带音乐/通知？建议首版只做时间/天气/系统，媒体与通知放 P1。
4. 图标收纳是否首版必须？建议 P1，复用现有图标网格，但作为组件重做。
5. 是否以单主屏为第一验收环境？建议是，多屏放 P2。
6. 是否有你正在用的 GlassBoard 版本/截图/推荐配置可作为视觉基准？有的话直接给，减少猜测。
7. 桌面图标“默认隐藏”是仅 Liuli 运行期间隐藏、退出恢复，还是永久写入系统设置？建议运行期隐藏，退出恢复；系统图标五个开关则按用户选择永久保存。
8. Dock 默认组合是否就按“此电脑、回收站、用户文件夹 + 文件资源管理器、设置、Edge、记事本、计算器”起步？后续可按 GlassBoard 实测调整。
9. 任务栏默认是否直接开“自动隐藏”？建议默认开、持久化，并提供“恢复系统任务栏”；“运行期完全隐藏”作为 P1 可选实验项，不默认开。
10. 配色默认是否开“跟随壁纸”？建议默认开；预设先做 6 套（雾蓝、石墨、暖砂、青瓷、紫雾、极简白），名称与色值可在设计阶段再定。
11. 多屏首版做到什么程度？建议默认仅主屏，P1 支持“所有屏 Dock + 主屏灵动岛”，每屏独立布局再往后放。
12. 文字大小用应用内四档，还是直接跟随 Windows 辅助功能文字缩放？建议应用内四档 + “跟随系统”选项。

## 11. 决策记录

- D-001：2.0 的产品基线改为 GlassBoard 功能对齐，不再以文件看板为核心。
- D-002：v1.x 用户功能封存，代码与数据保留；不删除用户文件。
- D-003：保留玻璃底、分层窗口、主题 token、配置、天气/系统读数等底层能力。
- D-004：先完成需求基线，未确认前不写新功能代码。
- D-005：视觉按 V0→V1→V2 三阶段推进，每阶段以截图评审为准。
- D-006：桌面图标默认隐藏；五个系统图标分“桌面可见”和“Dock 可见”两套开关，默认桌面全关、Dock 显示此电脑/回收站/用户文件夹；Dock 默认组合为系统入口 + Windows 自带应用，不复制桌面快捷方式。
- D-007：任务栏优先做“持久化自动隐藏”；Windows 没有受支持的永久隐藏 API，不替换 Explorer。完全隐藏只作为运行期可选实验项，退出恢复。
- D-008：配色以“跟随壁纸自动取色”为默认能力，可关闭；提供 6 套预设与自定义入口；所有组件只消费统一 Theme token，不允许单组件独立配色。
- D-009：屏幕适配采用 Per-Monitor V2；默认只主屏，多屏为可选；灵动岛默认只主屏，Dock 可选每屏；文字用应用内四档并允许跟随系统。
- D-010：UI 美观是 P0 发布闸门，不是最后再补的“润色”；每个里程碑按六项清单评审，不达标不进入下一阶段。

## 12. 验收定义（Definition of Done）

一个功能只有同时满足以下条件才算完成：

1. 对应 REQ 的验收标准逐条通过。
2. 真机截图/录屏留档，与参考图并排评审。
3. 视觉六项清单（对齐/间距/字号/材质/配色/动效）全部通过，无 P0 视觉缺陷。
4. 性能预算未回退（内存、闲置 CPU、启动时间）。
5. 配置可持久化，异常可回退。
6. 文档更新：README、DESIGN、TESTING、CHANGELOG。
7. 留痕：Issue、分支、PR、Release tag 齐全。
